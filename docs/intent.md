# M-Pilot: 물류 자동화 설비 장애 기술지원 서비스

> 고객사의 장애 신고에 대해 엔지니어가 매뉴얼과 과거 서비스 이력에서 대응 근거를 쉽게 찾아, 기술 지원 대응의 병목을 줄인다.

## 문제정의

고객사의 장애 신고에 대응하는 엔지니어는 방대한 매뉴얼과 과거 서비스 이력을 직접 찾아 대응 근거를 모아야 한다. 필요한 자료를 찾기 어렵고, 개인에게 쌓인 조치 경험도 다른 엔지니어가 활용하기 어렵다.

M-Pilot은 이 자료 탐색의 부담을 줄여 기술 지원 대응을 돕는다. 고객사 조치 대상에는 매뉴얼에서 관련 근거를 찾아 셀프 가이드를 제공하고, 그 밖의 장애는 엔지니어의 현장 기술지원을 돕는다. 확정된 현장 조치 결과는 다음 대응의 근거로 남긴다.

## 대상 사용자

- **기술지원 엔지니어**: 신고된 장애의 대응 근거를 찾고, 대응 방안을 검토하며, 실제 조치 결과를 기록한다.
- **고객사 담당자**: 장애를 신고하고, 접수·진행 상태와 자동 생성된 셀프 가이드 또는 엔지니어가 등록한 현장 조치 결과를 확인한다.

## 핵심 기능

1. **장애 셀프 가이드**: 접수된 신고 건의 심각도와 조치 구분을 바탕으로 셀프 가이드 대상인 경우, 시스템이 해당 설비의 매뉴얼을 근거로 관련 정보를 제공한다. 근거 부족·생성 실패 시에는 엔지니어 처리 건으로 접수한다.
2. **장애 대응 관련 근거 수집 지원**: 엔지니어는 신고 건별 채팅에서 LLM을 통해 후속 질문을 이어가며 현장 기술지원을 위한 관련 근거를 수집한다.
3. **서비스 이력 검색 근거 갱신**: 엔지니어가 서비스 이력 작성 화면에서 실제 원인·조치·결과를 등록하면 조치 완료되고 다음 RAG의 검색 근거가 된다. 자동 셀프 가이드는 내용·출처를 조회 이력으로 보존하되 검색 근거로 재사용하지 않는다. 완료 후 추가 지원은 새 신고로 받는다.

## 신고 대상과 활용 데이터

- **대상 설비**: Mini Loader, SRM, AGV, RTV 4종.
- **가상 매뉴얼**: 대상 설비 4종에 대한 매뉴얼(PDF).
- **가상 서비스 이력**: 설비별 50건, 총 200건을 초기 검색 자료로 활용한다.

## 무엇으로 성공을 확인하는가

- **답변과 근거의 적절성**: 장애 관련 질문에 적절한 답변을 제공하고, 인용한 매뉴얼·서비스 이력이 실제로 답변을 뒷받침하는지 평가한다.
- **대응 흐름의 연결**: 신고가 자동 셀프 가이드 제공 또는 엔지니어 RAG 채팅·현장 조치 기록으로 완료되는 흐름과, 가이드를 만들 수 없을 때 엔지니어 접수로 이어지는 것을 시연한다.
- **이력의 재활용**: 새로 확정한 조치 이력이 이후 질문에서 검색되고, 답변의 근거로 활용되는 것을 시연한다.

자료 탐색과 대응의 시간 단축은 기대 효과다. 이번 PoC에서는 답변 평가와 흐름 시연으로 가치를 확인하며, 실측 없이 시간 단축 효과를 주장하지 않는다.

## 지킬 범위와 원칙

- 가상 자료로 가능성을 검증하는 PoC이며, 실제 현장 도입은 이번 범위에 포함하지 않는다. 로그인은 데모 계정으로 화면의 역할만 나누며 실제 인증·보안이 아니다.
- 고객에게 제공하는 조치 안내는 매뉴얼의 안전 수칙을 따라야 한다. 분기는 에러코드 표의 심각도와 조치 구분만으로 결정하며(심각도 상은 조치 구분과 무관하게 엔지니어에게 접수한다), 고객 안내 절차는 매뉴얼에서 고객이 수행하도록 명시한 내용에 한정하며 과거 현장 이력은 고객 안내에 사용하지 않는다. 근거 부족·생성 실패 시 고객에게 조치를 추측해 제시하지 않고 처음부터 엔지니어 처리 건으로 접수한다.
- 대응 방안·답변에는 출처를 제시한다. 근거가 부족하면 추측하지 않고 이를 알린다.
- 신고한 설비의 매뉴얼·이력에서 근거를 찾지 못한 질문은 근거가 부족하다고 알린다. 보류 여부는 설비 종류가 아니라 검색 결과의 근거 유무로 정한다.
- AI는 엔지니어의 판단을 지원하며, 실제 조치 판단과 서비스 이력 결과 등록은 엔지니어가 맡는다.
